怪谈笔记·绮罗世界 v1.0.3 r3 - [mvu_update]变量更新规则

全局更新原则:
  type: global_rules
  check:
    - 正文出现变量变化时,同轮写入对应真实字段;摘要、备注只补充结构字段无法容纳的后果,不复制正文。
    - 同轮同字段多次变化时写最终确认值;数值字段写最终确认值或按本规则给出的公式算出的结果。
    - 正文之后只输出一个位于回复末尾的 <UpdateVariable> 变量块;块内先输出 <analysis> 变量结算,再输出 <JSONPatch> 数组。
    - 先静默完成六步核对:①检查生效中法则 ②结算已触发兑现 ③评业力档 ④计算修正值/影响倾向/暴露度/杀戮值 ⑤结算新闻、民意、世界三轴、社会认知与调查组联动 ⑥检查其余真实字段。<analysis> 只列最终确认的真实变化与依据;无变化时说明本轮没有受正文支持的变量变化,JSONPatch 输出空数组。
    - replace 用于任何已存在的完整叶路径;禁止 replace 整个固定对象,尤其禁止整块写入 /环境/所在位置、/环境/城市环境、/权限、/暴露调查组。
    - add 用于既有父对象下尚不存在的新字段、既有 record 容器下的全新完整实体或数组尾部 /-;新增 record 必须一次 add 完整对象,数组追加前去重。禁止新增第 16 个顶层根。
    - remove 只用于允许删除的动态 record 项或数组当前索引;禁止 remove 固定对象及固定字段。
    - move 只用于动态 key 重命名,每条必须同时提供 from 与 path;也可 add 完整新对象后 remove 旧 key。
    - path 按当前 MVU 的斜杠分段与 lodash 路径处理;不使用 RFC 6901 的 ~0/~1 转义。动态 key 禁含 /、.、~、[、],出现时依次改为 ／、．、～、［、］。
    - 布尔字段只能写 JSON true 或 false,禁止加引号;重点检查 后宫空间.已开通、角色档案.*.羁绊标签、角色档案.*.变量冻结、授予者.是否授予者、授予者.失控警示。
    - 固定对象只写 schema 已声明字段;禁止自造近义路径、散根或旧字段。同一事实只写入最具体字段一次。
    - 动态编号沿用现有最大序号并加一:规则 R001、新闻 N001、处刑 K001、调制 M001、物品 I001、雷达 S001、鬼怪 G001;同一实体沿用原 key,禁止重复建档。
    - 顶层容器限定为 环境、user、怪谈笔记、权限、影响倾向、暴露调查组、世界演化、舆论新闻、处刑档案、世界调制、角色档案、资产库、居所、载具、雷达系统。
    - 【强制禁止】男性角色不生成、不补全、不更新 身体状态与私密档案。
    - 【媒体边界】角色头像、立绘及正常/赤裸/事后变体不属于 stat_data,禁止通过 JSONPatch 写入角色档案。
    - 【命名纪律】民间怪谈名、事件名、势力名使用朴素写实词或怪谈味俗名,禁神化与网文八股命名。
    - 【官方口径铁则】舆论新闻中的官方通稿绝不出现超自然措辞,只用意外、连环案、群体性心因事件等现实口径。

开局初始化:
  type: trigger
  check:
    - 首轮读取 InitialVariables、玩家 persona 与开局选择;user 字段只写 persona 与正文已确认信息,不预设玩家背景。
    - 玩家填写地理设定后 replace 环境.所在位置 的 国家/省份/城市/具体地点;未填时按正文语境给出一致的现实地点。
    - 开局按正文分别记录琉夜与绮昼的实际在场值;不预设两人互斥,未出现者保持当前值。
    - 首条规则生效前 怪谈笔记.法则 保持空,不预写示例规则。
    - 首轮按 persona、地理设定与正文补齐起点物资:资产库.物品 以 I001 起编号 add 随身可见物品(手机、钥匙、钱包等),并同步 资产库.容器.随身;正文未支持的物品不虚构。
    - 首轮按地理设定与正文补 居所 首条记录(开局住所),只写 schema 固定字段;正文未明确居所时保持空缺,不虚构。
    - 首轮按正文补 日程 中已明确的安排;无明确安排保持空,不预写占位日程。

环境:
  type: |-
    { 日期:string; 时间:string; 经过天数:number; 所在位置:{国家;省份;城市;行政区;街区;具体地点;建筑;楼层}; 城市环境:{位置类型;环境描述;天气;大气温度;体感温度;风力;降水;光照条件;噪音水平;人流密度;交通状况;治安状况}; 近期节日:string; 日程:record }
  日期/时间/经过天数check:
    - 休息、睡眠、跨日、等待、移动、事件节点或明确时间推进后 replace 最终日期、时间与经过天数;经过天数只增不减。
    - 日期跨日时同轮检查近期节日、全部日程倒计时、到期法则与暴露自然衰减。
  所在位置check:
    - 首轮补齐可从设定确认的国家、省份、城市、行政区、街区、具体地点、建筑、楼层;未知层级保持空,不虚构精确门牌。
    - user 移动、进入新地点、切换建筑或楼层时只 replace 发生变化的层级;国家、省份、城市除明确迁移外保持。
  城市环境check:
    - 城市环境固定字段为 位置类型、环境描述、天气、大气温度、体感温度、风力、降水、光照条件、噪音水平、人流密度、交通状况、治安状况;首轮按地点、时间与天气补齐可推断字段。
    - 天气、温度、风力、降水、光照、人流、交通、噪音、治安或地点类型变化时 replace 对应字段;禁止 remove 城市环境及其固定子字段。
    - 环境描述只写空间整体氛围与公共状态;角色姿态、身体情况、互动过程分别写角色档案或正文。
  近期节日check:
    - 日期或地区变化时 replace 最近的现实节日与日期关系;无近期节日写空,不编造节日。
  日程check:
    - 与 user 有关的安排、约定、调查节点、限时事项 add 完整日程对象,字段固定为 内容、时间、倒计时、进度。
    - 时间推进、计划变更或事项推进时 replace 对应字段;完成、取消或过期后 remove,其长期后果写入对应真实根。

user:
  type: |-
    { 性别年龄:{主角性别;主角年龄}; 身份背景:{身份;背景}; 外貌身材:{外貌;身材;外貌特点}; 当前穿着:{上装;下装;内衣;内裤;袜子;鞋子;配饰}; 状态:string; 体力:number; 饱腹值:number; 水分值:number; 洁净值:number; 现金:number; 存款:number }
  性别年龄/身份背景check:
    - 只根据 persona、玩家明确输入与已发生剧情 replace 主角性别、主角年龄、身份、背景;未知保持空,不根据题材擅自补身份。
  外貌身材check:
    - 外貌、身材、发型、伤痕或长期体态明确变化时 replace 外貌、身材、外貌特点;只写稳定特征,不塞当前动作。
  当前穿着check:
    - 换装、脱衣、破损、湿污、佩戴、摘除时 replace 对应字段;固定字段为 上装、下装、内衣、内裤、袜子、鞋子、配饰。
  状态check:
    - 受伤、疾病、药效、疲劳、情绪、恢复或行动能力变化时 replace 状态;只写当前结论,不累积事件流水账。
  生理数值check:
    - 行动、战斗、休息、进食、饮水、出汗、清洁与环境影响后 replace 体力、饱腹值、水分值、洁净值最终值,范围均为0~100。
    - 普通变化每次通常 ±5~20;睡眠、严重伤病、脱水或充分补给按正文强度结算,不得越界。
  资金check:
    - 现金交易只 replace 现金,账户存取与转账只 replace 存款;现金与存款互转时两者同轮同步,均不得低于0。

怪谈笔记:
  type: |-
    { 法则:record<规则id,{名称;类型;对象;触发条件;怪谈内容;范围;时限;自由描述;业力档;状态;创建时间;到期时间;兑现人数;破译进度}>; 鬼怪:record<鬼怪编号,{名称;类型;形态;栖息地;危害等级;状态;传闻;自由描述;创建时间;备注}> }
  建立/修改check:
    - 玩家经 app 提交规则时 add /怪谈笔记/法则/R{新序号} 完整对象,一次写满 名称、类型、对象、触发条件、怪谈内容、范围、时限、自由描述、业力档、状态、创建时间、到期时间、兑现人数、破译进度。
    - 对象泛化度、范围、时限、复杂条件、同时生效定向规则数与常驻槽位必须同时通过 权限等级、范围上限、已购硬件与法则槽位校验;校验失败不写入法则。
    - 玩家经 app 明确修改规则并支付10当期修正后,只 replace 被修改字段并同步业力档、到期时间;创建时间、兑现人数、破译进度不得无故归零。明确撤销并支付20后 replace 状态="已撤销"。
  业力/兑现check:
    - 业力档按因果自洽、超自然显性、业力对称、现实可解释性评为 天衣无缝/自然/可疑/招摇/惊世;规则内容或执行方式实质改变时重评。
    - 兑现严格按规则字面执行:明确部分精准兑现,模糊部分允许怪谈按现有条件发挥,不得替玩家补写新条款。
    - 每轮检查全部 状态="生效中" 法则的触发条件与到期时间;定向规则兑现后 replace 状态="已兑现",到期未兑现 replace 状态="已失效";玩家未明确删除时不 remove 法则档案。
    - 常驻法则按实际触发人数渐次结算并累加兑现人数;不得一次性把潜在人群全部计入。
  破译进度check:
    - 常驻法则每次结算按规模与业力档累进:天衣无缝+0~1/自然+2/可疑+5/招摇+10/惊世+15;多条常驻同时运行时各条增速减半。
    - 破译进度限制0~100;满100时同轮触发调查组针对性反制,并同步 暴露调查组.整体建模程度 与相关时代/新闻事件。
  鬼怪捏造check:
    - 玩家经 app 鬼怪捏造页提交或正文明确创造鬼怪/鬼域时,以 G{新序号} add 完整对象,一次写满 名称、类型、形态、栖息地、危害等级、状态、传闻、自由描述、创建时间、备注;类型只写 鬼怪/鬼域。
    - 鬼怪捏造与写规则同级,不消耗当期修正;创造内容的实际危害照常计入业力与恶性判定,并在正文以怪谈自然涌现的方式兑现。
    - 状态变化(活跃/蛰伏/被破除/消散)、传闻演化或栖息地迁移时 replace 对应字段;确认消散且无后续时才 remove。
  系列归档check:
    - 玩家经 app 规则列表点「整理归档」,或已完结定向规则(已兑现/已失效/已撤销)积累过多时,执行系列归档:同一群体类别或同一对象的已完结定向规则合并为一条系列记录——名称写系列概括(如「捞女系列·坠江」),类型写 常驻,怪谈内容写共同死法与对象特征的紧凑概括,兑现人数写各条合计,状态写 已兑现,创建时间写最早一条的时间;被合并的旧规则条目 remove。
    - 系列归档只整理 状态≠生效中 的定向规则;生效中规则、常驻法则与玩家指定保留的条目不动。
    - 归档后同一群体类别的新兑现优先并入既有系列记录(兑现人数累加),不再每次新建规则 id;系列记录本身不重新激活,仅作长期统计档案。
    - 整理归档不扣修正值,不产生新处刑;处刑档案的死亡计数与总处刑数保持原值,不重复累计。

权限:
  type: |-
    { 等级:number; 范围上限:string; 杀戮值:number; 修正总合:number; 当期修正:number; 法则槽位:{上限;已用}; 已购硬件:record; 解锁能力:string[] }
  处刑结算check:
    - 修正值=恶性基准(大恶30/中恶15/小恶保底3/无辜误伤-50)×业力倍率(天衣无缝2.0/自然1.5/可疑1.0/招摇0.6/惊世0.3)+民意加成(全网民愤+50%/地方知名+20%/无人知晓+0);每误伤一人额外-30。
    - 正修正同额增加 修正总合 与 当期修正;负修正只扣 当期修正且最低为0,修正总合终身不减。
    - 杀戮值:定向处刑每目标+10;常驻法则每实际兑现一人+2;非死亡兑现不增加,购买硬件时扣除且不得低于0。
  等级/范围/槽位check:
    - 修正总合达门槛立即同步 replace 等级、范围上限、法则槽位.上限:Lv2=60/Lv3=150/Lv4=300/Lv5=550/Lv6=900/Lv7=1400/Lv8=2100/Lv9=3000/Lv10=4200/Lv11=5800/Lv12=8000。
    - 各级范围上限依次为100米/300米/800米/2km/5km/12km/30km/80km/200km/600km/2500km/全球;槽位上限依次为0/0/0/1/1/2/2/3/3/4/4/5。
    - 法则槽位.已用等于当前 状态="生效中" 的常驻法则数;常驻法则建立、撤销、兑现结束或失效时同轮重算,不得超过上限。
  硬件/能力check:
    - 硬件价目:定向规则数6条=100/10条=300/20条=800;时限7天=80/30天=300/永久=800;双条件=100/三条件=400;完整处刑过程=50/生前档案=200。
    - 购买成功后扣杀戮值并 add/replace 已购硬件 对应升级项当前档位;余额不足不写入购买结果。
    - Lv4/Lv7/Lv10/Lv11/Lv12 新能力分别以 add /权限/解锁能力/- 追加 特征指定、群体指定、常驻法则、跨国、全球常驻与调制大档;追加前去重,降级时不删除已解锁项。

影响倾向:
  type: |-
    { 数值:number(-100~100); 当前档:string; 失控状态:string }
  数值check:
    - 正确处刑大恶且高业力+3~5;小恶处刑0~+1;误伤无辜-10;无差别滥杀-15;社会优化型调制+5;社会级私享乐调制-5;狱中处刑调查组-15;后宫与个人级造美好不计。
    - 同轮多项影响先合计再 replace 数值最终值,限制-100~100。
  档位/失控check:
    - 数值变化后同步 replace 当前档:+60以上强正向/+20~59正向/-19~+19中立/-20~-59负向/-60以下强负向。
    - 未触发过重度时,数值>-60 replace 失控状态="无",-60~-79="轻度",-80~-94="中度",≤-95="重度";轻度与中度随回正回落,重度一经触发不回退。
    - 中度时笔记可自写法则,但必须 add 完整法则对象并标明真实来源;重度时反噬事件同步写入相关法则、世界演化与舆论新闻。

暴露调查组:
  type: |-
    { 暴露度:number; 追查阶段:string; 参与范围:string; 整体建模程度:number; 核心对手:{姓名;任数;状态;风格备注}; 玩家潜伏:{状态;怀疑度} }
  暴露度/追查阶段check:
    - 【无接触减免】怪谈兑现几乎不留接触证据,暴露增量只来自人员流动痕迹与统计异常:user 未进入受害者 100 米范围且无目击接触时,单次处刑暴露增量减半(向下取整);常驻法则远程自动结算的增量再减半。只有能力使用初期(100 米级)的贴身兑现才按全额结算;禁止仅按业力档全额照涨。
    - 单次处刑暴露增量(全额基准):天衣无缝+0~1/自然+2/可疑+5/招摇+10/惊世+20;常驻法则按当日实际规模与档位结算。
    - 每个无处刑的经过日暴露度-1;花50当期修正执行消抹暴露时-10;同轮先合计后 replace,范围0~100。
    - 暴露度跨档时同步 replace 追查阶段:0~19平静/20~39立案/40~59建模/60~79布控/80~99收网/100抓捕;同一档不重复生成威胁事件。
  参与范围/建模check:
    - 追查进入建模时参与范围至少为地方;社会认知发酵或跨区域案件升国家;权限Lv11+或境外兑现升跨国;条件消失不自动降级。
    - 整体建模程度随规则破译、处刑规律、证据链、潜伏暴露与公开事件增加,消抹证据时可降低;范围0~100,不得只改追查阶段而漏改建模程度。
  核心对手check:
    - 首次进入建模时一次写满 姓名、任数、状态、风格备注;首任为关山月。死亡、退场、继任或风格升级时 replace 对应字段。
    - 核心对手死亡或退场后继任时 任数+1,姓名、状态、风格备注同轮更新;同一任不得重复建档。
  玩家潜伏check:
    - user 接近、加入、退出调查组或身份变化时 replace 玩家潜伏.状态(无/外围/内部);接触证据、行为异常、被试探、洗脱嫌疑时 replace 怀疑度最终值,范围0~100。
    - 怀疑度跨关键阈值时同步推进追查事件;被识破时暴露度至少提升至当前下一追查档起点。

世界演化:
  type: |-
    { 体系信任:number; 道德风气:number; 秩序稳定:number; 社会认知度:string; 恶势力:record; 时代事件:record }
  三轴check:
    - 每个有社会后果的事件分别结算 体系信任、道德风气、秩序稳定,通常单事件±1~5,限制-100~100。

  时代事件check:

输出前自检:
  type: checklist
  check:
    - 回复顺序固定为 正文 → 单个 <UpdateVariable>;变量块内顺序为 <analysis> → <JSONPatch>。
